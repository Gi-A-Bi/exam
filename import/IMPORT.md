# 옛 시스템(구글 시트) 데이터 가져오기

기존 GAS 시스템의 **정답지 + 응시 결과**를 새 프로그램으로 그대로 옮기는 절차입니다.
약 10분 소요. 학생 데이터가 채팅/외부로 나가지 않고 **구글 시트 → 내 Supabase** 로만 이동합니다.

## 옮겨지는 것 / 아닌 것

| 항목 | 이관 여부 |
|---|---|
| 정답지 (문항·정답) | ✅ 그대로 |
| 응시 결과 (점수, 문항별 ⭕❌, ⚠검토 표시, ✏️수동정정, 제출 시각) | ✅ 그대로 (재채점하지 않음) |
| 교사 비밀번호 | ❌ 옮길 수 없음 → 교사가 **옛 시스템과 같은 코드**로 새로 가입해야 데이터가 연결됨 |
| 반/학생 PIN | 옛 시스템에 없던 개념 → 옛 기록은 "반 미지정"으로 표시됨 (조회·그래프 정상) |

## 0단계. 교사 재가입 (필수 선행)

데이터를 연결할 교사가 새 프로그램에 **옛 시스템에서 쓰던 것과 똑같은 코드**(예: KIM01)로
가입되어 있어야 합니다. 코드가 다르면 그 교사의 데이터는 이관에서 제외됩니다.

## 1단계. 구글 시트에서 CSV 내려받기 (2분)

옛 시스템의 스프레드시트를 열고, 시트(탭)별로:

1. **answer_keys** 시트 탭 클릭 → 메뉴 **파일 → 다운로드 → 쉼표로 구분된 값(.csv)**
2. **submissions** 시트 탭 클릭 → 같은 방법으로 다운로드

(teachers/settings 시트는 필요 없습니다)

## 2단계. 스테이징 테이블 만들기 (1분)

Supabase 대시보드 → **SQL Editor** → `import/1_staging.sql` 내용 붙여넣기 → **Run**

## 3단계. CSV 업로드 (3분)

1. 대시보드 → **Table Editor** → 왼쪽 목록에서 **staging_answer_keys** 클릭
2. 상단 **Insert → Import data from CSV** → 1단계의 answer_keys CSV 선택 → 열 매칭 확인 → Import
3. **staging_submissions** 테이블에도 같은 방법으로 submissions CSV 업로드

> 열 이름이 자동으로 매칭됩니다(시트 헤더와 동일하게 만들어 둠). 매칭 안 되는 열이 보이면
> 그대로 진행하지 말고 화면을 캡처해서 알려주세요.

## 4단계. 변환·적재 (1분)

SQL Editor → `import/2_transform.sql` 붙여넣기 → **Run**

실행 결과로 리포트가 표시됩니다:
- `이관된 정답지 / 이관된 응시 결과` — 성공 건수
- `가입 필요(매칭 안 된 교사코드)` — 이 코드로 가입한 교사가 없어 제외된 것 (0단계 후 재실행하면 포함됨)
- `제외된 응시 결과` — 교사 미가입이거나, 옛 시험이 이미 삭제되어 연결할 수 없는 기록

## 5단계. 확인 후 정리

프로그램에 교사로 로그인해서:
- **정답지 관리**에 옛 정답지들이 보이는지
- **응시 결과 / 학생별 분석**에 옛 기록·그래프가 보이는지

확인되면 SQL Editor 에서 `import/3_cleanup.sql` 실행(임시 테이블 삭제).

## 주의

- 2단계~4단계를 **두 번 실행하면 데이터가 중복**됩니다. 한 번만 실행하세요.
  (실수로 중복됐다면 알려주세요 — 정리 SQL을 만들어 드립니다)
- 옛 기록은 반(class) 정보가 없으므로 결과 화면에서 반 필터에 걸리지 않고,
  학생별 분석에서는 이름 기준으로 묶입니다.
- 옛 기록의 시험들은 "모든 반 공통"으로 들어가므로 **학생 시험 목록에도 나타납니다.**
  학생이 응시하면 안 되는 옛 시험은 정답지 관리에서 [수정]으로 응시 반을 조정하거나,
  기록 보존이 필요 없으면 삭제하세요(⚠ 삭제 시 그 시험의 응시 결과도 함께 삭제됨).
